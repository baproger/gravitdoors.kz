# Виртуальный хостинг hoster.kz (Plesk): как развернуть

Сайт живёт на виртуальном хостинге hoster.kz, тариф «Турбо-1»: 15 ГБ диска,
1 ГБ памяти, 2 vCPU, панель **Plesk**, на сервере есть PHP 8.3 и 8.4. Root-доступа,
nginx-конфигов, swap и systemd здесь нет — всё делается через панель. Инструкция
для VPS (`docs/server.md`) остаётся на случай переезда; про память и фон там
всё верно и для хостинга.

Проект собран под **PHP 8.3+** (`composer.json` → `config.platform.php = 8.3.0`),
на сервере выбираем **8.4**.

## Куда кладётся код

Код должен лежать **выше** веб-корня: наружу отдаётся только `public/`.

```
/var/www/vhosts/<домен>/
├── gravit/            ← репозиторий (artisan, app, vendor, storage …)
│   └── public/        ← веб-корень домена
└── httpdocs/          ← штатный каталог Plesk, не используется
```

## Шаги в Plesk

**1. PHP.** Сайты и домены → домен → *Настройки хостинга*: версия PHP **8.4**,
режим **FPM-приложение** (обслуживается nginx). Там же ниже — *Настройки PHP*:

| Параметр | Значение | Зачем |
|---|---|---|
| `memory_limit` | 128M | страница панели — 65–75 МБ на пике |
| `max_execution_time` | 60 | зависший запрос не должен держать процесс |
| `upload_max_filesize` / `post_max_size` | 10M / 12M | чеки и договоры до 10 МБ |
| `opcache.enable` | on | обычно уже включён |
| `opcache.memory_consumption` | 64 | если поле есть |

Дополнительные директивы (поле «Дополнительные директивы конфигурации»), если
панель их принимает:

```
opcache.save_comments = 1
opcache.jit = off
realpath_cache_size = 4096k
```

**2. Git.** Сайты и домены → домен → *Git* → «Добавить репозиторий»:
удалённый репозиторий `git@github.com:baproger/gravitdoors.kz.git`, ветка `main`,
каталог развёртывания `gravit` (не `httpdocs`). Plesk покажет **публичный
SSH-ключ** — добавить его в GitHub: репозиторий → Settings → Deploy keys
(только чтение), или с рабочей машины:

```bash
gh repo deploy-key add key.pub -R baproger/gravitdoors.kz -t "hoster.kz plesk"
```

Режим развёртывания — автоматический (webhook) или ручной кнопкой «Развернуть».
В «Действиях при развёртывании» вписать:

```
bash deploy/plesk-deploy.sh
```

Этот скрипт ставит composer-пакеты, генерирует `APP_KEY`, делает бэкап, накатывает
миграции, кэширует конфиг и перезапускает режим обслуживания. Если действия при
развёртывании у подписки недоступны (нет shell), скрипт запускается из планировщика
(шаг 5) или используется архив релиза (шаг 4).

**3. Веб-корень.** Сайты и домены → домен → *Настройки хостинга* → «Корневой
каталог документов»: `gravit/public`.

**4. Без Git и Composer: архив релиза.** На рабочей машине
`bash deploy/build-release.sh` собирает `deploy/release/gravit-<дата>.zip` с
`vendor` внутри. Plesk → *Файлы* → загрузить архив в каталог `gravit` →
«Извлечь файлы». Дальше запустить `bash deploy/plesk-deploy.sh` по SSH или через
планировщик (шаг 5): composer он не найдёт и возьмёт `vendor` из архива.

**5. Планировщик.** Сайты и домены → домен → *Запланированные задачи* →
«Добавить задачу», тип «Выполнить команду», **каждую минуту** (`* * * * *`):

```
/opt/plesk/php/8.4/bin/php /var/www/vhosts/<домен>/gravit/artisan schedule:run
```

Внутри Laravel сам решает, что запускать: 03:00 бэкап, 08:00 проверка сервера,
08:30 сводка по складу и цеху. Путь к PHP нужной версии — именно
`/opt/plesk/php/8.4/bin/php`: `php` без пути на хостинге может оказаться старым.

Через такую же одноразовую задачу удобно выполнять любые artisan-команды, если
нет SSH: например установку (шаг 7).

**6. .env.** Plesk → *Файлы* → `gravit/.env` (создаётся из
`.env.production.example` при первом запуске `plesk-deploy.sh`, либо скопировать
руками). Заполнить:

```
APP_URL=https://<домен>
SESSION_SECURE_COOKIE=true
TRUSTED_PROXIES=127.0.0.1,::1
DB_HOST=localhost
DB_DATABASE=<из Plesk → Базы данных>
DB_USERNAME=<там же>
DB_PASSWORD=<там же>
```

База создаётся в Plesk → *Базы данных* → «Добавить базу данных»; кодировку
выбрать `utf8mb4` (сравнение `utf8mb4_unicode_ci`), если панель спрашивает.

**7. Первый запуск.** По SSH (`cd ~/gravit`) или одноразовой задачей планировщика:

```
/opt/plesk/php/8.4/bin/php artisan gravit:install --name="Имя" --email=director@example.kz --password=<пароль>
```

Команда накатывает миграции, заполняет справочники без демо-данных (этапы обеих
воронок, 13 этапов цеха, склад, касса и банк, прайс) и создаёт директора. Повторный
запуск справочники не трогает.

**8. HTTPS.** Сайты и домены → домен → *SSL/TLS-сертификаты* → Let's Encrypt,
включить «Постоянное перенаправление на HTTPS». `APP_URL` с `https://` — иначе
подписанные ссылки на файлы выйдут с `http://` и не откроются.

**9. Второй фактор.** Войти директором → профиль → «Двухфакторная аутентификация» →
привязать приложение-аутентификатор, сохранить коды восстановления. То же —
бухгалтеру. Файлы (чеки, договоры) лежат в `gravit/storage/app/private` и наружу
не смотрят: веб-корень — только `gravit/public`.

## Обновление

Закоммитить и запушить в `main` → Plesk → Git → «Развернуть» (или автоматически
по webhook). Действия при развёртывании запустят `plesk-deploy.sh`. Без Git:
собрать новый архив `build-release.sh`, распаковать поверх, запустить скрипт.

Перезагружать PHP-FPM не нужно: на хостинге opcache сам проверяет файлы на
изменение (`validate_timestamps` включён).

## Проверка, что всё живо

- `/opt/plesk/php/8.4/bin/php artisan gravit:server-check --dry` — свободный диск,
  возраст бэкапа. Память на виртуальном хостинге команда показать не сможет:
  `/proc/meminfo` там про весь узел, а не про ваш лимит — эту строку игнорируйте.
- Plesk → домен → *Журналы* — ошибки PHP и nginx.
- Plesk → домен → *Статистика* — сколько диска занимают файлы и бэкапы
  (`gravit/storage/backups`, 14 копий базы и 3 архива файлов).

## Ограничения хостинга, о которых надо помнить
- **Сжатие загрузок** работает через GD (есть в PHP Plesk): фото чеков и договоров
  худеют в 10–20 раз ещё до записи на диск. PDF пережимается только при наличии
  Ghostscript — на виртуальном хостинге его обычно нет, PDF остаются как есть.
  `memory_limit` 128M хватает на снимки до ~16 мегапикселей; более крупные приходят
  уже уменьшенными браузером, а если нет — сохраняются как есть.

- **Память 1 ГБ на всю подписку**, PHP-процессов у FPM обычно 2–5. Опрос
  уведомлений раз в 2 минуты и планшет раз в 15 секунд в это укладываются.
- **Нет swap и нет root**: если сайт упирается в память, единственный ход —
  тариф выше или VPS (`docs/server.md`).
- **Бэкапы** лежат на том же диске в `storage/backups`; Plesk делает свои
  еженедельные копии всей подписки — это вторая линия, не отключать.
- Бэкапу нужны `exec()`, `mysqldump` и `tar`. Если `gravit:backup` пишет
  «mysqldump не отработал», проверить *Настройки PHP* → `disable_functions`
  (там не должно быть `exec`) и написать в поддержку hoster.kz, есть ли
  `mysqldump` на узле. Вторая линия — еженедельные копии самого Plesk.
